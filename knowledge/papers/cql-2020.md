# CQL: Conservative Q-Learning for Offline Reinforcement Learning (Kumar et al., NeurIPS 2020)

**Authors:** Aviral Kumar, Aurick Zhou, George Tucker, Sergey Levine · **Lab:** UC Berkeley · **Venue:** NeurIPS 2020 · **arXiv:** 2006.04779

## What it is

CQL is an offline RL algorithm that prevents value overestimation on out-of-distribution (OOD) actions
— the core failure mode of standard Q-learning applied to a fixed dataset. It augments the standard
Bellman-error TD loss with a conservative regularizer that pushes Q-values DOWN on actions drawn from
an auxiliary distribution μ (e.g., uniform or the current policy) and UP on actions that appear in the
data (under the behavior policy π_β). The result is a Q-function that lower-bounds the true value on
in-distribution actions while not inflating estimates on unseen ones.

## Why it matters here

The exp0045/0046 diagnosis pinpointed our length-2 execution wall as **reward-head OOD overestimation**:
the WM reward head ranks ~12% of random action sequences above the only truly rewarding gesture. CQL's
conservative regularizer is directly portable from a Q-function to a reward estimator: replace Q with
R_hat, sample "random" or "model-imagination" actions as the OOD set, and add the penalty to the
standard reward-prediction loss. This gives a conservative reward head that underestimates reward on
unseen action sequences — exactly the fix exp0047 implements.

## Details (method depth)

### The offline distributional-shift problem

Standard off-policy Q-learning bootstraps using a target that includes max_a Q(s', a). When the
dataset does not cover all actions, Q(s', a) for OOD a is fit to nothing — it can be arbitrarily
large. The Bellman update then propagates these inflated estimates back, compounding across temporal
depth. The result: the policy trained on argmax Q chases hallucinated high-value OOD actions it never
saw during collection. Concretely measured in exp0045: ~12% of random 2-action sequences are scored
above the true gesture by the WM reward head.

### The CQL regularizer (arxiv:2006.04779 §3)

CQL adds a term to the standard Q-learning objective:

```
min_Q  α · [E_{s~D, a~μ}[Q(s,a)]  −  E_{s~D, a~π_β}[Q(s,a)]]
        + standard TD error
```

- **Push DOWN**: E_{a~μ}[Q(s,a)] — expected Q under an auxiliary distribution μ over OOD actions.
  μ can be uniform over the action space, the current policy, or any other broad distribution.
- **Push UP**: E_{a~π_β}[Q(s,a)] — expected Q under the data distribution (behavior policy); prevents
  the penalty from suppressing the Q estimates the policy needs.
- **α** controls the tradeoff. Large α → very conservative (may under-estimate); small α → falls back
  toward standard Q-learning. α can be fixed or tuned via a Lagrangian dual formulation that targets
  a gap threshold.

### The logsumexp variant

For continuous action spaces, the expectation E_{a~μ}[Q(s,a)] is approximated via importance sampling
or replaced with the logsumexp over sampled actions:

```
CQL regularizer = α · [log Σ_a exp(Q(s,a)) / |A|  −  E_{a~π_β}[Q(s,a)]]
```

The logsumexp acts as a soft-maximum over action samples, placing most weight on the highest-Q action
in each sampled set — a tighter proxy for the worst-case OOD inflated Q than a uniform average.

### Why it lower-bounds the true Q

Under mild assumptions (behavior policy support), the CQL regularizer guarantees that the resulting
Q-hat satisfies Q-hat(s,a) ≤ Q^π(s,a) for all (s,a) pairs in the dataset — i.e., it is a
conservative lower bound on the true policy value. This makes the resulting policy safe in the offline
sense: argmax Q-hat does not chase ghost optima outside the data support.

### Portability to a reward head (the key insight for exp0047)

The regularizer is agnostic to what it penalizes. Substituting R_hat for Q:

```
min_R  α · E_{s~D, a~random}[R_hat(s,a).clamp_min(0)]   ← push DOWN overestimates on OOD actions
        + E_{s~D, a~replay}[(R_hat(s,a) − r)²]            ← standard MSE on in-distribution data
```

The one-sided relu (`.clamp_min(0)`) is the sparse-reward adaptation: we only penalize positive
overestimates (false positives that mislead the planner), not all predictions. This is exactly the
"CROP online variant" that exp0047 implements.

## Open questions

- **Optimal α**: The paper offers a Lagrangian schedule but the default is task-sensitive. For our
  sparse setting (one reward event per episode), α needs to be large enough to kill the ~12% false
  positives without suppressing the true gesture signal.
- **μ choice**: The paper compares uniform-random vs current-policy as μ. For exp0047 we use
  uniform-random OOD actions sampled from the detached belief; whether belief-conditioned sampling
  or truly uniform is better is open.
- **Dense vs sparse rewards**: CQL's evaluation is on continuous-control with dense rewards (D4RL).
  The conservative bias in a sparse-reward setting (where most rewards are 0) may behave differently —
  the push-down term essentially sees only the rare positives as "in-distribution".

## Relevance to our work

Direct ancestor of the exp0047 conservative reward head. The connection chain:

- **exp0025** ([[0025-reward-head-patch]]): two-hot distributional reward head bounded reward
  MAGNITUDE (fixed MSE over-prediction for the Crafter actor). First reward-head fix.
- **exp0045** ([[0045-rtfm-oracle-probe]]): oracle probe showed the reward head ranks the true gesture
  only ~88th percentile among random sequences — OOD overestimation, not fidelity.
- **exp0046** ([[0046-rtfm-robust-planning]]): sampled-rollout MPC (K=10) shaved some prior-mean
  optimism but plateaued at 0.92 — planning-time fix is insufficient; training-time fix required.
- **exp0047** ([[0047-rtfm-conservative-reward]]): implements the one-sided-relu CQL push-down
  directly on the reward head at WM-train time, sampling M=16 OOD actions per step from the detached
  belief. The `reward_conservative_coef` α and `reward_conservative_samples` M are the CQL knobs.

See also [[crop-2023]] for the closest published instantiation of conservative reward heads in MBRL.
